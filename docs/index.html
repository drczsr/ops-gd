01 / 背景与价值

从「散落的脚本」到「统一控制台」

大规模游戏服运维的痛点不在单台操作，而在规模化下的可审计、可回滚、可观测。这套平台把高频高危的运维动作收口成标准工单。

改造前

配置散落在 SVN，改服靠手工脚本
批量操作逐台 SSH，效率低、易漏
无审批、无留痕，误操作难追溯
下发出错无法回滚，状态不可见

改造后

配置入库受管，行级 diff、一键全服下发
256+ 服批量启停 / 发版 / 合服一处操作
五段状态机审批留痕，角色门禁
COS 版本控制做基准，可防覆盖、可回滚
02 / 核心能力

九大模块，覆盖运维全链路

从工单审批、服务器管控、配置下发，到发版热更、合服、新建服向导与即时通知，构成完整的运维操作面。

01

工单流程引擎

提交 → 审批 → 执行 → 测试 → 开放 五段状态机；角色门禁、审批 / 驳回、全程操作留痕。

02

服务器实例管理

256+ 服集中视图；SSH 并发实时探测状态、启停 / 强杀 / 修复 / 内存启动、批量操作、登录限制、包版本展示。

03

游戏服配置中心

配置库受管替代 SVN；表格化批量编辑、行级 diff、一键生成与发布。

04

全服配置下发

建单冻结快照 + 线上 diff；COS 版本控制做基准防覆盖，审批通过后全服热下发。

05

发版与全服热更

换包、DB 版本逐级升级（包版本解析 + 库版本比对）、分波重试、GM 热更下发。

06

合服与合服预告

合服 / 预合服工单一体化；合服预告配置库化受管，提交即生成、一键发布。

07

创建游戏服向导

自动算 ID、紧凑选机、分配端口、联动建战斗 / 中心服；事务写库、自动建库与 ALB 转发。

08

企业微信通知

工单 9 个关键节点状态变化，自动推送群机器人并 @ 对应责任人。

09

菜单与权限

按用户的菜单访问门禁，路由 + 侧边栏双重校验；敏感页面仅管理员可见。

03 / 功能详解

关键场景，深入看

选取五个最能体现设计深度的模块展开。截图均已脱敏处理。

/orders · 工单引擎

工单流程引擎

系统的中枢。把合服、发版、热更、配置下发等高危操作统一收口为工单，按五段状态机流转、留痕、按角色门禁。

  • 多类工单：合服 / 发版 / 热更 / 全服更新 / 合服预告 / 新建服 等统一入口
  • 五段状态机：提交 → 审批 → 执行 → 测试 → 开放，逐段流转、全程留痕
  • 执行时机：审批后立即执行，或定时执行（按计划时间触发）
/servers

服务器实例管理

云控制台风格的集中视图，把 256+ 台游戏服的状态、版本、网络与操作收进一张表。

  • 实时状态探测：SSH 有界并发跑状态脚本，在线 / 异常 / 离线一目了然
  • 多种启停：启动 / 优雅停 / 强制停 / 修复启动 / 内存启动，强杀拦截防误启
  • 批量与版本：多选批量操作、登录限制下发、包版本随状态一并探测展示
/gsconfig · 配置中心

游戏服配置中心

把原本散落在 SVN 的服配置全量入库受管，表格化编辑、一键生成与全服下发，配置变更从此可追溯。

  • 配置入库受管：替代 SVN，按列建模、行即一台服，可增删改查与分区筛选
  • 表格化批量编辑：Handsontable 批量改字段，改动行级高亮，所见即所得
  • 生成与下发：一键生成 ServerConfigList、全服更新、批量创建、导入 / 导出
/gsconfig/create

创建游戏服向导

三步向导把「开新服」从一长串手工脚本，变成填几个字段、系统自动编排的一站式动作。

  • 自动编排：号池发号、紧凑选机、分配端口档、联动建战斗 / 中心服
  • 事务写库：预览不落库、确认后事务批量写入，全成功或回滚
  • 一站到底：部署、建库（Create_DB）、开服、自动建 ALB 转发规则一气呵成
角色 · 权限

成员角色与权限

基于角色的访问控制：把「谁能提交、谁能审批、谁能执行」固化成矩阵，再叠加菜单级门禁。

  • 角色矩阵：提交 / 审批 / 执行 / 测试 / 管理员 多角色自由组合
  • 菜单门禁：按用户开放服务器管理 / 游戏服配置 / 合服预告等页面，路由 + 侧边栏双重校验
  • 最小授权：管理员 override 全菜单，普通成员按需单独开页，凭据安全收口
04 / 技术架构

服务端渲染 + 真实执行器

一个 Go 单体应用，向上服务端渲染轻前端，向下并发驱动 SSH、数据库、对象存储与云资源。

服务端渲染 + 渐进增强Gin + html/template 服务端渲染，少量原生 JS 增强；零重前端框架依赖，部署简单。
真实执行器 · 双模式系统 ssh/scp 有界并发（护住 sshd），mock / real 双模式可本地安全演练，不触生产。
COS 原生版本控制配置下发以线上版本为基准防并发覆盖，支持精确回滚到任一历史版本。
异步通知不阻塞企业微信通知异步发送，失败只记日志，绝不阻塞工单主流程流转。
05 / 工程实践

不只是能跑，是可靠

面向生产高危操作的工程纪律：测试先行、幂等可重试、三重防误操作、凭据零外泄。

测试驱动开发（TDD）

关键路径单测覆盖，全量 go test 通过；改动均先红后绿。

幂等与断点续跑

建组 / 写库 / 部署前先查存在性，工单重试不产生重复副作用。

失败子集自动重试

分波重试只补跑失败的服，不重跑已成功步骤，缩短恢复时间。

三重防误操作

基准校验 + 强杀拦截 + 审批门禁，把高危动作拦在执行之前。

凭据零外泄

DB 密码只在内存连接串，绝不进命令、日志或前端响应。

规格驱动迭代

spec → plan → 分任务实现，复杂功能先对齐设计再动手。
